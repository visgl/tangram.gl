# What's New

## November 2026

- `heatmap` layers are drawn as MapLibre GL JS draws them: each point of a vector or GeoJSON source adds a Gaussian kernel of `heatmap-radius` pixels, scaled by `heatmap-weight` and `heatmap-intensity`, to a density a quarter of the canvas's size, and the density is colored by the `heatmap-color` ramp over `["heatmap-density"]`, with `heatmap-opacity`. A heatmap sums the points of all of its tiles before it is colored, and draws in style order. Also on a globe and in a `_CustomProjectionView`. WebGL only (WebGPU draws no heatmap).
- A `vector`, `raster` or `raster-dem` source can take its tiles from a PMTiles v3 archive, `"url": "pmtiles://<archive URL>"`, as with the `pmtiles` protocol of MapLibre GL JS. The archive header gives the source's `minzoom`, `maxzoom` and `bounds`. The header, the directories and the tiles are read with HTTP range requests, with the `fetch` and `fetchOptions` of `loadOptions`, so an application can serve its basemap from its own origin with no tile server. See [PMTiles archives](./developer-guide/style-specification-support.md#pmtiles-archives).
- A new `style` object for `BasemapLayer` keeps the TileJSON, the tiles and the decoded data of each source whose definition did not change, and the loaded sprites and glyphs, as MapLibre GL JS's `setStyle(style, {diff: true})` keeps them. Before, each new style object loaded and decoded every tile again. A source is decoded again when the style draws a different set of its source layers.
- A new `style` object that changes only what loads nothing (paint and layout values, filters, zoom ranges, the order and the visibility of the layers) applies in the same update, as MapLibre GL JS's `setStyle(style, {diff: true})` applies it: `BasemapLayer` compares the two styles with `diff` from `@maplibre/maplibre-gl-style-spec` and does not resolve the style again. The next frame draws the change.
- `BasemapLayer`'s `mode` prop takes `'auto'`, the new default. The layer reads the mode from the viewport: globe sublayers in a deck.gl `GlobeView`, map sublayers in other views, as MapLibre GL JS draws a style in the projection of its map. Apps no longer compute `mode` from their view. `'map'` and `'globe'` still override the viewport.
- `BasemapLayer`'s new `sourceData` prop gives the data of `geojson` sources by source id, as MapLibre GL JS's `GeoJSONSource.setData` does: a GeoJSON object or a URL, in place of the source's `data` in the style. Each entry is compared by identity. When one changes, only that source is indexed and cut again: the style does not load again, and the other sources keep their tiles. See [`sourceData`](./api-reference/basemap-layer.md#sourcedata).
- `BasemapLayer`'s new `getStyleLayerProps` prop gives extra deck.gl props, such as `extensions` and their props, to the sublayers of one style layer: for example, mask only the roads. It is called for each style layer when the style or the function changes, not for each tile.

- The new `insertLayers` prop of `BasemapLayer` draws deck.gl layers between the layers of the style, as MapLibre GL JS's `addLayer(layer, beforeId)`: for example a data layer above the water and below the roads. One basemap draws both parts of the style, and a source's tiles load once. The inserted layers are picked as top-level layers. An unknown `beforeId` raises an error to `onError`. See [`insertLayers`](./api-reference/basemap-layer.md#insertlayers).

- API consistency of `@tangram.gl/basemap-layers`: the root exports `BasemapLayerProps`, `BasemapLayerLoadOptions`, `BasemapGlobeConfig` and the style types (`BasemapStyle`, `ResolvedBasemapStyle` and their layer and source types). `style` is an optional prop, as its default is `null`. `getGlobeBaseLayers` is deprecated: it logs a warning one time, and it now passes every option to `getBasemapLayers`, `tilesets` and `fetch` included. `getGlobeTopLayers` takes no required options. The package copy of the API reference is generated from the website copy (`node scripts/sync-basemap-docs.mjs`), and both document every prop and root export.

- `BasemapLayer` raises each resource of the style that fails to load to deck.gl's `onError` layer prop, and then to the `onError` of the `Deck`, in place of a log message that an application could not read. The error is a `BasemapLoadError`, with the `kind` of resource (`style`, `source`, `tile`, `sprite`, `glyphs` or `image`) and its `sourceId`, `url`, HTTP `status` and tile index where they apply. Each failure is raised once, and a cancelled request is not raised. See [`onError`](./api-reference/basemap-layer.md#onerror).
- A style URL loads with the `fetch` and `fetchOptions` of `loadOptions`, as its sources, sprites and glyphs do. Before, the style document was requested with the global `fetch`.
- `BasemapLayer` takes a `transformRequest` prop, as MapLibre GL JS's `transformRequest` map option: one function that can change the URL, headers and credentials of each request the layer makes, with the resource type of the request (`'Style'`, `'Source'`, `'Tile'`, `'Glyphs'`, `'SpriteJSON'` or `'SpriteImage'`). It covers the style, TileJSON, GeoJSON data, vector, raster and raster-dem tiles, sprites and glyphs. See [`transformRequest`](./api-reference/basemap-layer.md#transformrequest).
- A style URL is fetched with the `fetch` and `fetchOptions` of `loadOptions`. Before, the first request of the style ignored them, and a style behind authentication failed to load.

- `BasemapLayer#querySourceFeatures(sourceId, {sourceLayer, filter})` returns the features of a `vector` or `geojson` source in the tiles drawn now, in longitude and latitude, as MapLibre GL JS's `Map#querySourceFeatures`. See [Methods](./api-reference/basemap-layer.md#methods).
- `BasemapLayer`'s `style` prop accepts a style that `resolveBasemapStyle` or `MapStyleLoader` returned. Such a style draws at once, without a second fetch of its TileJSON and GeoJSON data, and its relative `sprite` and `glyphs` URLs still resolve against the URL that it was loaded from. `isResolvedBasemapStyle` (from `/map-style`) tells such a style from a copy.
- In a projected view and on a globe, `geojson` sources are cut at the edge of Web Mercator tiles, at 85.051129 degrees north and south. Points past it are not drawn, and lines and polygons end where they cross it. Before, geojson-vt moved them onto the edge: in a south polar view, a point at -89.5 degrees drew on the -85.05 degree parallel. The layer warns once per source that has such features. `MapView` draws them as before, as MapLibre GL JS does. See [Projected views](./api-reference/basemap-layer.md#projected-views).
- `background-pattern` draws the sprite image across the map, as MapLibre GL JS draws it: repeated from the map's origin, so it moves with the map, at its size at the integer zoom, scaled with the map between integer zooms, times `background-opacity`. Also on a globe, and in a projected view at the size of the Web Mercator map of the same scale. Before, a patterned background drew nothing. WebGL only.
- `BasemapLayer` reports its loading as deck.gl's `TileLayer` does. `isLoaded` is `false` while the style resolves, while its sprites load and while the tiles of the viewport load. Before, it was `true` for an empty map while the style loaded. The new `onStyleLoad`, `onTileLoad` and `onViewportLoad` props report the resolved style, each loaded tile and the loaded viewport. The new `onAttributionChange` prop reports the attribution of the sources that the style draws, as `TangramLayer` does.
- In a `_CustomProjectionView` whose coordinate reference system is on another body, such as the Moon (`+proj=eqc +R=1737400`) or Mars, `hillshade` layers shade slopes by the radius of that body: the semi-major axis of the CRS. Before, they used the size of the Earth, and slopes on the Moon were drawn 3.67 times too flat. Maps, globes and projected views on the Earth draw as before.
- `color-relief` layers over `raster-dem` sources are drawn, in style order, as MapLibre GL JS 6.13 draws them: `color-relief-color`, an `interpolate` ramp over `["elevation"]`, `color-relief-opacity` and `resampling`, with the `mapbox`, `terrarium` and `custom` encodings. They share the decoded tiles of their source with its `hillshade` layers, and draw on a map, on a globe and in a projected view. Against MapLibre GL JS for the same DEM tiles, the median pixel is identical. They also draw on WebGPU, with the same colors as on WebGL.
- `hillshade` layers draw on WebGPU, with the same shading as on WebGL: every `hillshade-method`, the illumination direction, altitude and anchor, `hillshade-exaggeration`, the shadow, highlight and accent colors, and `resampling`. Before, WebGPU drew no hillshade.
- `line-pattern` draws sprite images along lines, per feature, as MapLibre GL JS draws them: stretched across the line and repeated along it at their aspect ratio, in the `line-width` of the integer zoom, times `line-opacity`.
- `line-gradient` draws over lines of a `geojson` source with `lineMetrics`, as MapLibre GL JS draws it: each line colored by its `line-progress` from its start to its end, across the tiles it crosses, times `line-opacity`.
- `text-rotate` turns point labels clockwise, per feature, as MapLibre GL JS turns them: about the point, with their `text-anchor` and `text-offset`. They collide with the box around the turned text.
- `icon-text-fit` and `icon-text-fit-padding` stretch an icon over its label, as MapLibre GL JS does, for road shields and label backgrounds. The sprite's `stretchX` and `stretchY` zones stretch while its corners and edges keep their size, `content` marks the part of the image that the label covers, and `textFitWidth` / `textFitHeight` keep the aspect ratio of `content`. The fitted icon collides by its fitted box. WebGL and WebGPU.
- `raster` layers draw `image` sources, as MapLibre GL JS 6.13 draws them: the image at its four `coordinates`, with `raster-opacity`, the color adjustments (`raster-brightness-min`, `-max`, `-saturation`, `-contrast`, `-hue-rotate`) and `raster-resampling`, as raster tiles take them. A quad that is not a rectangle is warped as a perspective view of the image, as MapLibre warps it, also on a globe and in a projected view. The `url` resolves against the style URL.
- Sources draw their tiles as MapLibre GL JS does with `scheme` and `bounds`, from the style or from a TileJSON. `scheme: "tms"` flips the tile row in the tile URLs of `vector`, `raster` and `raster-dem` sources, and tiles outside a source's `bounds` are not requested. See [Source tiles](./developer-guide/style-specification-support.md#source-tiles).
- Raster tiles fade in over `raster-fade-duration`, as in MapLibre GL JS (default 300 ms): a newly loaded tile cross-fades from the nearest ancestor tile that was loaded, enlarged, and a tile without one fades in from transparent. A raster layer reports loaded once its tiles have faded in. WebGL only.
- `line-translate`, `fill-extrusion-translate` and `circle-translate-anchor` are drawn, with `fill-translate`'s `map` and `viewport` anchors: the offset is on the ground, and turns with the map or, for `viewport`, keeps its direction on the screen. Before, lines and extrusions were drawn untranslated, and a circle's offset did not turn with the bearing. WebGL only; on WebGPU circles keep their previous pixel offset.
- Sprite images are decoded unpremultiplied, as deck.gl decodes its own images. Before, the icon layers blended the premultiplied colors with their alpha again, so translucent pixels drew too dark: the soft white rims of icons, as in the Esri sprites, showed as gray rings.
- `BasemapLayer` draws in a deck.gl `_CustomProjectionView`, a flat view in a projected coordinate reference system such as a UTM zone or a conic projection. Web Mercator tiles are selected for the area the screen shows. Fills and lines are projected at each vertex, raster and hillshade tiles are drawn on a mesh that follows the projection, and labels stay upright. Styles are evaluated at the zoom of the Web Mercator map of the same scale. See [Projected views](./api-reference/basemap-layer.md#projected-views). `getProjectedTileIndices`, `ProjectedTileset2D`, `ProjectedBitmapLayer` and `getMercatorZoom` are exported for other tiled layers.
- `BasemapLayer`'s new `zoomLoadDelay` prop holds vector tile loads while a view zooms, so a zoom gesture does not decode and triangulate the tiles of each tile zoom it passes through. Tiles that a loaded ancestor covers wait until the zoom comes to rest; tiles that no view selects then are not loaded. The default, `0`, keeps the previous behavior.
- On WebGPU, `BasemapLayer` draws the raster color adjustments (`raster-brightness-min`, `-max`, `raster-saturation`, `-contrast` and `-hue-rotate`) with MapLibre GL JS's formulas, as on WebGL. Before, WebGPU drew raster tiles unadjusted. `circle-blur` also fades circles, `fill-pattern` draws its images, `fill-translate` moves fills, and `fill-extrusion` layers are shaded from the style's `light` with `fill-extrusion-vertical-gradient`, on WebGPU. On a map, `fill-translate` now moves a fill's pattern with the fill, as in MapLibre; before, the pattern stayed in place.
- `["feature-state", key]` reads the new `featureState` prop of `BasemapLayer` in the paint of `fill`, `line`, `circle` and `fill-extrusion` layers, as MapLibre GL JS reads `setFeatureState`. A state change updates only the paint attributes of the style layers that read it, without new tiles or new geometry. With `pickable: true`, picked features of vector and GeoJSON sources are named in `info.basemapFeature`: the style layer id, the source, the source layer, the feature id and its properties. See [`featureState`](./api-reference/basemap-layer.md#featurestate) and [Picking](./api-reference/basemap-layer.md#picking).

## October 2026

- Relative `tiles` in a TileJSON whose URL is an ArcGIS service root without a trailing slash (`.../VectorTileServer` or `.../MapServer`) resolve below that root. Before, the last path segment was dropped and the tile requests failed.
- Labels are drawn with the style's `glyphs`, as in MapLibre GL JS: the signed distance fields of each `text-font` stack, loaded per range as tiles need them, with MapLibre's advances and glyph placement. A tile's labels are placed once their glyphs have loaded. Styles without `glyphs`, and the `fontFamily` prop, still draw with the browser's fonts.
- Point labels place by `text-variable-anchor` and `text-variable-anchor-offset`, as MapLibre GL JS does: each label tries its anchors in order and is drawn at the first where it collides with nothing, instead of being dropped, with its icon left at the point. `text-radial-offset` offsets the text from the point in the anchor's direction, also with a fixed `text-anchor`, and `text-justify: auto` follows the anchor the label is placed at.
- `hillshade` layers over `raster-dem` sources are drawn, in style order, as MapLibre GL JS 6.13 draws them: `mapbox`, `terrarium` and `custom` encodings, a TileJSON `url` or inline `tiles`, every `hillshade-method` (`standard`, `basic`, `combined`, `igor`, `multidirectional` with up to four lights), `hillshade-illumination-direction`, `-altitude`, `-anchor`, `-exaggeration`, `-shadow-color`, `-highlight-color`, `-accent-color` and `resampling`. Tiles take their neighbors' edge pixels, so they join without seams. A source's tiles are fetched and decoded once, and shared by all of its `hillshade` layers, also through a switch between a map and a globe; direct `getBasemapLayers` callers can keep them across calls with `createDemTileset`. Also on a globe; WebGL only (WebGPU draws no hillshade).
- Style layers of a `geojson` source draw, cut into tiles on the client by `@maplibre/geojson-vt`, as MapLibre GL JS cuts them, in a web worker (on the main thread where none can start), and then drawn as vector tiles: `fill`, `line`, `circle`, `symbol` and `fill-extrusion` layers, on a map and on a globe. `data` is a GeoJSON object or a URL, fetched when the style resolves (relative to the style URL, with the `fetch` and `fetchOptions` of `loadOptions`). `maxzoom`, `buffer`, `tolerance`, `generateId`, `promoteId` and clustering (`cluster`, `clusterRadius`, `clusterMaxZoom`, `clusterMinPoints`) are supported; `clusterProperties`, `lineMetrics`, `filter` and `attribution` are not.
- Labels take their font from `text-font` instead of a fixed `Monaco, monospace`: each font name maps to a CSS family list with a generic fallback, plus a weight and style (`Noto Sans Bold` is `"Noto Sans", sans-serif` at weight 700). `BasemapLayer`'s new `fontFamily` prop overrides the family, or maps the font names with a function; `fontFamily: 'Monaco, monospace'` keeps the previous look.
- Symbol layers draw `icon-image` from the style's sprite (`@2x` on high-density screens, the `[{id, url}]` sprite array, `icon-size`, `icon-opacity`, `icon-anchor`, `icon-offset`, and `icon-color` for SDF images). Labels honor `text-offset` and `text-anchor`. Missing sprites and images are skipped with a warning.
- `line-width` is drawn as the style sets it: the OpenMapTiles-specific scaling (0.55 for `transportation`/`boundary`, 0.75 for `waterway`/`aeroway`) is removed, a width of 0 draws nothing, and wide lines are no longer capped at 20 px.
- Style evaluation uses `@maplibre/maplibre-gl-style-spec` instead of `@mapbox/mapbox-gl-style-spec`. Evaluated colors keep the same `[r, g, b, a]` shape (RGB 0-255, alpha 0-1).
- Style layers draw within their own `minzoom`/`maxzoom` only. A source's `maxzoom` no longer hides layers past it; its last tiles are overzoomed instead.
- Zoom-dependent style values are evaluated in 0.25 zoom steps instead of at integer zooms, so widths and colors no longer jump a whole zoom level at a time. Tiles regenerate at each step. Filtered features are kept per tile and style layer and reused across steps; they are recomputed only when a filter reading `["zoom"]` crosses an integer zoom, so other steps do not re-tessellate. Label paint is evaluated once per style layer and step.
- `line-sort-key` orders a line layer's features within a tile as MapLibre GL JS orders them, lowest key first: where lines cross, the one with the higher key draws on top, as on OSM Americana's roads, bridges and route lines. Dashed, offset and blurred lines are ordered too, also on a globe. Lines in different tiles are not ordered by key, and a `line-gap-width` draws one side of every line's gap before the other.
